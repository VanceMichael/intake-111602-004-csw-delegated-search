# 资料服务接口

查询参数顺序不影响来源匹配。区域目录与根目录会返回相同本地 identifier，区域目录还指回根服务；覆盖状态与异常独立于命中记录。

CSW 响应保留 XML 标准字段。/capabilities 和 /regional/csw 是既有网关提供的 JSON 调试视图，含委托路径、异常及本次查询覆盖；不能将其 complete:false 转为空结果。来源标识空间由服务入口区分。

本地服务的资料入口为 `/csw?service=CSW&request=GetRecords`。`fixtures/ordinary.json` 记录当前可预览的资料；`fixtures/transition.json` 保存资料源连续两个发布日期；`fixtures/federation.json` 提供多目录委托场景，含只转回部分子站的网关、异常报告站与断连站。调用 `POST /control` 并传入 `{"action":"advance"}` 推进发布日期，`inspect` 返回实际请求记录，`reset` 恢复本地源；控制入口不属于远端标准协议。来源分段、延迟和断连均可用场景条目的 `chunks`、`delayMs`、`disconnect` 配置，不需要依赖实际网络故障。

原件目录采用内容摘要寻址，接收凭据独立记录来源、媒体类型和预览结果。单份资料接收不表示来源范围已经读完，也不推断缺失资料的业务含义。

## 跨目录资料领取

`POST /harvests` 在单站预览之外执行一次跨目录领取，请求体可含：

- `roots`：根目录入口列表，缺省取 `profile.harvestRoots`；
- `conditions`：本次检索条件，作为查询参数附加到每个被实际检索的入口（如 `anyText`、`bbox`）；
- `hopBudget`：委托跳数预算，根目录能力文档中的 `hopCount` 会进一步收紧它；
- `full`：是否按来源能力领取完整元数据，缺省为 true。

执行规则：

1. 对每个**实际检索**的入口先取同目录能力文档（如 `/csw` -> `/capabilities`、`/regional/csw` -> `/regional/capabilities`），读取 `typeNames`、`elementSetNames`、`recordRetrieval` 与 `delegates`；能力文档取不到只登记不确定项，不阻断检索。
2. 遍历状态按次查询独立构建：一个目录即使被别的查询访问过，本次条件下仍会重新检索；同一入口在本次查询内重复出现时按回路截断（`loop-cut`），不重复发请求，也不把被截断入口记为空结果。
3. `complete:false`、异常报告（`exception-report`）、断连（`unreachable`）、跳数超限（`hop-limit`）分别登记到 `uncertainties`，绝不折算成“命中 0 条”。
4. 记录身份是 `服务入口#identifier`：简略记录里相同的 identifier 若分属不同入口则各自保留，并汇总到 `sharedIdentifiers`。各站 `matched/returned` 只在 `coverage` 中按来源列示，不跨目录相加。
5. 完整元数据按该站能力文档声明的 `recordRetrieval` 领取：`csw-getrecordbyid` 走 `GetRecordById&elementsetname=full`，`record-link` 走模板路径；领取结果经内容摘要目录留存接收凭据，失败或未声明领取方式同样进入不确定项。

`GET /harvests` 列出历次报告，`GET /harvests/<报告编号>` 回读单份报告。报告中的 `coverage` 说明本次条件覆盖到哪家目录、委托链与各站状态，`uncertainties` 说明哪里仍不确定。
