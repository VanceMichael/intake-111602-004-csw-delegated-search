# 资料服务接口

查询参数顺序不影响来源匹配。区域目录与根目录会返回相同本地 identifier，区域目录还指回根服务；覆盖状态与异常独立于命中记录。

CSW 响应保留 XML 标准字段。/capabilities 和 /regional/csw 是既有网关提供的 JSON 调试视图，含委托路径、异常及本次查询覆盖；不能将其 complete:false 转为空结果。来源标识空间由服务入口区分。

本地服务的资料入口为 `/csw?service=CSW&request=GetRecords`。`fixtures/ordinary.json` 记录当前可预览的资料；`fixtures/transition.json` 保存资料源连续两个发布日期；`fixtures/federation.json` 提供跨目录委托场景（真空目录、部分覆盖、无领取入口节点）。调用 `POST /control` 并传入 `{"action":"advance"}` 推进发布日期，`inspect` 返回实际请求记录，`reset` 恢复本地源；控制入口不属于远端标准协议。来源分段、延迟和断连均可用场景条目的 `chunks`、`delayMs`、`disconnect` 配置，不需要依赖实际网络故障。

原件目录采用内容摘要寻址，接收凭据独立记录来源、媒体类型和预览结果。单份资料接收不表示来源范围已经读完，也不推断缺失资料的业务含义。

## 跨目录资料领取

`POST /harvest` 在一次领取内完成下列动作，领取状态只属于本次请求，不做跨查询缓存：

1. 先读根站 `/capabilities`，记录其 `typeNames`、`elementSetNames`、返回模式、委托入口与 `hopCount`；委托到的 JSON 视图没有独立 capabilities 时，按响应内嵌的 `delegates`、`exceptions`、`complete` 记录其返回模式。
2. 沿委托树逐站检索。节点身份按 `来源源 + 路径名` 归一化，查询参数顺序不同仍视为同一目录；同一节点在本次委托中再次出现即判定为回路，边标记为 `loop` 并停止沿该回路转发；深度超过 `hopCount`（默认取配置上限与来源声明值的较小者，请求显式传入 `hopLimit` 时以请求为准）的边标记为 `hop-limit`。止境只针对本次条件：另一次领取即使访问过同一目录，也会带着本次 `condition` 重新检索。
3. 每个节点保留实际检索来源、逐页请求、命中简报（含来源命名空间）、异常与截断状态。`complete:false`、`exceptions`、非 200 响应、传输失败、翻页中断都进入 `uncertainties`，节点状态为 `incomplete`/`error`；只有完整响应且零异常、零命中才记为 `empty`。任何异常都不会折算成空结果。
4. 完整元数据按来源支持的标识领取：CSW 节点向自身入口发 `GetRecordById&elementsetname=full`；JSON 调试视图节点在能沿本次委托树回到 CSW 网关时，委托该网关领取并把 `delegatedClaim` 记为 true；与 CSW 网关断开的节点没有领取入口，记为 `unsupported`。相同 identifier 来自不同机构时按简报来源分别领取、分别生成凭据，不因同号而合并。领取失败进入 `uncertainties`，简报记录不能替代完整元数据。

领取报告通过 `GET /harvests` 列表、`GET /harvests/<报告标识>` 回查，原件仍按摘要保存在 `objects/`，完整元数据凭据保存在 `receipts/`，报告保存在 `reports/`。报告的 `coverage.nodes` 给出每个目录的条件覆盖与状态，`coverage.edges` 给出委托边及 `followed`/`loop`/`hop-limit`/`unresolved` 结局，`claims` 给出每份完整元数据的简报来源、领取入口与凭据，`uncertainties` 汇总所有不能确定的部分；负责人据此核查条件覆盖到哪家目录、哪里仍不确定，而不是只得到一张混合资源表。
